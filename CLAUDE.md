# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`olux-studio/backend` is a **multi-tenant website builder / CMS** built on **Laravel 13 + Livewire (Volt) + Tailwind 4**. Authenticated users own **Sites**; each Site is composed of Pages, reusable Components, and content. Sites can be edited visually, generated by an **LLM agent** from natural-language prompts, extended with installable **Features** (store, donations, Twitter feed), previewed publicly, and **exported as a static Nuxt 4 app** to disk or a GitHub repo.

## Commands

```bash
composer dev          # Run everything: php serve + queue listener + pail logs + vite (concurrently)
composer test         # Clears config, then runs the Pest suite
php artisan test                         # Run all tests
php artisan test --filter=DashboardTest  # Single test class
php artisan test tests/Feature/Auth      # A directory/suite
php artisan serve     # App server only
php artisan queue:listen --tries=1       # Queue worker (jobs: site generation, exports)
php artisan pail      # Tail application logs
npm run dev           # Vite dev server (admin assets) only
npm run build         # Build admin assets
./vendor/bin/pint     # Lint/format (Laravel Pint) — the project's code style tool
```

Tests use an in-memory `testing` DB with sync queue (see `phpunit.xml`). The framework is **Pest**, not plain PHPUnit — write tests in Pest style.

## Architecture

### Two front-ends, one backend
- **Admin app** = server-rendered **Livewire components** in `app/Livewire/` (e.g. `PageBuilder`, `WireframeBoard`, `SitePrompt`, `MarketplacePage`). Routes are auth-protected and registered in `routes/web.php`; some via `Volt::route(...)`.
- **Public/generated sites** consume the **JSON API** in `routes/api.php` (`SiteContentController`, form/contact/subscription/media endpoints). These routes are **stateless — no session, no CSRF, `throttle:api`** — and are what Nuxt templates read at build/preview time.

### Core content model (read several models together to understand)
```
Site ─┬─ Pages ──(page_component pivot, ordered)── Components ── Nodes (self-nested tree via `parent`, ordered)
      ├─ Components (site-level, reusable)
      ├─ Wireframes ── WireframeBlocks   (the design/layout layer; kind = 'layout' for reusable wrappers)
      ├─ Collections, Media, Forms, Contacts, Products, Orders, Donations, Subscriptions
      └─ SiteAttributes / PageAttributes  (EAV key-value config; use $site->getAttr()/setAttr())
```
- **Nodes** are the atomic content units (text/boolean/etc. typed values) and form a tree within a Component.
- A **Page** renders by composing its ordered Components; a Component renders its Node tree. Pages reference a `Wireframe` layout (`layout_id`).
- Prefer the `getAttr/setAttr/forgetAttr/attrMap` helpers on Site/Page over touching the attribute tables directly.

### Wireframe → real content pipeline
`app/Wireframe/BlockCatalog.php` defines a catalog of block types. Each block's shape (name + default nodes) mirrors `TemplateContract`, so committing a wireframe (`WireframeService::commit()`) resolves each block **1:1 into a real Component + default Nodes**. The `{site_name}` placeholder in node values is substituted at commit time — same convention as `TemplateService::scaffold()`. `app/Templates/` holds full-site templates (`TemplateRegistry` + per-template classes implementing `TemplateContract`).

### LLM agent ("prompt a site")
- `SiteAgent` assembles a system prompt from instruction files in `resources/ai/` and runs an inference + tool-use loop. It does **not** call the model directly — it delegates to a bound `LlmDriverInterface`.
- `LlmServiceProvider` binds the driver from the `LLM_DRIVER` env var (`anthropic` | `deepseek` | `ollama`); all three implement the same contract. `SiteAgent::configured()`/`reachable()` gate the UI.
- `SiteTools` exposes the agent's capabilities (create page/component/form/product, add nodes, toggle features, apply templates, create/commit wireframes, …). `definitions()` returns the tool schemas; `execute()` dispatches by name and returns `ok()`/`err()` arrays. **When adding an agent capability, add both a definition and an `execute()` case here.**

### Feature system (the "App Store")
- `config/features.php` is the **single source of truth** for installable features — metadata, `needs_payments`, admin `nav` items (shown only when enabled), and a settings schema (`text|number|select|textarea|toggle`) the Marketplace renders into a form. `FeatureRegistry` reads this config; never hardcode feature lists elsewhere.
- Per-site gating is the **`feature:` middleware** (`EnsureFeatureEnabled`), e.g. `->middleware('feature:store')` in `routes/web.php`. Public store/donation routes live behind it.

### Payments
Stripe Checkout via `app/Services/Stripe/StripeGateway.php`, used by `StoreFrontController` and `DonateController`. **Webhooks are CSRF-exempt** (`preview/*/store/webhook`, `preview/*/donate/webhook` in `bootstrap/app.php`) and verified by Stripe signature instead.

### Static export
`SiteFileGenerator` bakes a Site into a complete **Nuxt 4** app under `public/sites/{folder}/`, copying from the canonical `nuxt-template/` and writing all site data into `public/content.json` so the built site renders without the live API. `GithubExporter` then pushes that bundle to a per-site GitHub repo using the **GitHub REST/Git Data API** (blobs → tree → commit → ref) — no `git` binary required. Heavy generation/export work runs through queued **Jobs** (`app/Jobs/`); run a queue worker locally.

### Routing order matters
`routes/web.php` is order-sensitive: static feature segments (store/donate/feed) are declared **before** the `/preview/{siteName}/{pageUrl}` catch-all (`PublicPageController`), and `auth.php` is required first. Keep new public routes above the catch-all.

## Conventions
- **`bootstrap/app.php`** (not `Kernel.php`) is where middleware aliases, CSRF exemptions, and providers are registered (Laravel 11+ structure).
- Config is the seam: LLM driver, features, and Stripe are all driven by `config/*` + env. Read `config/services.php` and `config/features.php` before wiring new integrations.
- `resources/ai/` holds the agent's persona/instructions/prompt-handling docs and an `ollama/` Modelfile — edit these to change agent behavior rather than hardcoding prompts.
- `*.bak` files (e.g. `SiteConfigure.php.bak`) are stale backups, not active code.
